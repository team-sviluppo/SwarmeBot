# Skill universali

Stato: implementato sul branch `feat/skills`, da provare dal vivo con un modello vero.

## Obiettivo

Un repository di skill gestito da SwarmeBot, sul motore, che vale per tutti i
motori dei bot (Claude, Codex, Pi, Antigravity, ACP, DeepSeek Harness, Local
Endpoint, Grok, Box), sul Mac e sui motori remoti. Come i connettori: il bot
sceglie quali skill vede, la chat le accende e spegne.

Non si toccano le cartelle dei provider (`~/.claude/skills`, `~/.codex/skills`…):
le loro skill native continuano a caricarsi come prima, a parte.

## Decisioni

- **S1 — Formato.** Quello delle Agent Skills: una cartella con `SKILL.md`
  (frontmatter YAML con `name` e `description`, poi le istruzioni) e
  qualunque sottocartella (`scripts/`, `references/`, `assets/`…). `name` è
  l'id: minuscole, cifre e trattini, al massimo 64 caratteri, uguale al nome
  della cartella. `description` al massimo 1024 caratteri.
- **S2 — Dove vivono.** `<data>/skills/<id>/` sul motore, oppure la cartella
  scelta in Impostazioni › Skill (`config.json` → `skills.folder`): una
  cartella condivisa (OneDrive, Dropbox, disco di rete) fa vedere le stesse
  skill da più postazioni. Nessun indice a parte: la cartella è la verità, si
  rilegge a ogni elenco e a ogni turno, quindi ciò che arriva da un'altra
  postazione vale subito (l'app lo vede quando riapre le impostazioni). Le
  cartelle sincronizzate spesso perdono il bit di esecuzione: l'indice dice al
  bot di lanciare gli script con l'interprete.
- **S3 — Import via API, con i byte.** `POST /api/skills` riceve i file
  (percorso relativo, contenuto base64, flag eseguibile), non un percorso del
  Mac: così funziona identico su un motore remoto via HTTPS. Limiti: 200 file,
  8 MB in tutto (il base64 cresce di un terzo e una richiesta si ferma a 12 MB),
  percorsi senza `..` né file nascosti, niente link simbolici. Si importa una
  cartella o un `.zip`/`.skill` che la contiene.
- **S4 — Sicurezza.** Una skill con script fa eseguire codice ai bot: l'app
  avvisa e chiede conferma all'import quando la skill contiene file diversi da
  Markdown/testo.
- **S5 — Sul bot.** `bot.skills = [{id, defaultOn}]` (max 50), come
  `bot.connectors`. Sulla chat: `task.skills = {id: bool}`, solo le scelte che
  differiscono dal default del bot.
- **S6 — Nel turno, automatico.** Nel prompt di sistema un indice delle skill
  accese: nome, descrizione, percorso di `SKILL.md`. Il modello lo apre quando
  la richiesta corrisponde. Per i motori senza filesystem (Local Endpoint, Grok,
  Box: `Library.mode == .inline`) va il testo intero di `SKILL.md`, entro un
  budget; i file accessori lì non sono raggiungibili.
- **S7 — Nel turno, forzato.** `/id` nel messaggio, per una skill assegnata
  al bot (anche se spenta nella chat): il motore mette il testo intero di
  `SKILL.md` nel testo del turno, prima del messaggio. Il messaggio salvato
  resta quello scritto dall'utente. Funziona anche da routine e webhook, perché
  è testo.
- **S8 — Eventi.** Ogni modifica del repository manda `{"kind": "skills"}` sullo
  stream; l'app ricarica l'elenco.

## API

| Metodo | Percorso | Note |
|---|---|---|
| GET | `/api/skills` | `{skills: [skill]}` |
| POST | `/api/skills` | `{files: [{path, content, executable?}], replace?}` → 201 `{skill}`; 409 se esiste e `replace` non è vero |
| GET | `/api/skills/<id>` | `{skill, content}` (testo di `SKILL.md`) |
| PUT | `/api/skills/<id>` | `{content}`: riscrive solo `SKILL.md`; il `name` non può cambiare |
| DELETE | `/api/skills/<id>` | toglie la skill anche da bot e chat |
| GET/PUT | `/api/skills-folder` | `{folder, defaultFolder, custom}`; PUT `{folder: path\|null}` |
| PATCH | `/api/bots/<id>` | `skills: [{id, defaultOn}]` |
| PATCH | `/api/bots/<id>/tasks/<thread>` | `skills: {id: bool}` |

`skill` = `{id, name, description, files: [path], bytes, tokens, hasScripts, updatedAt}`.

## App

- Impostazioni › Skill: cartella delle skill (scegli, mostra nel Finder,
  torna al default; su un server remoto è un percorso sul server), elenco,
  «Importa…» (cartella o zip, con conferma se ci sono script e se il nome
  esiste già), «Nuova skill», modifica di `SKILL.md`, elimina, «Copia su
  server» verso un motore remoto.
- Bot › Dettagli › Skill: interruttore per skill e «Accesa nelle nuove chat».
- Composer: chip delle skill della chat (come i connettori) e suggerimenti
  quando si scrive `/`.

## Fuori da questa fase

- Elenco in sola lettura delle skill native dei provider.
- Tool MCP `load_skill` per i file accessori sui motori senza filesystem.
- Import da URL/GitHub e dal catalogo dei team.
